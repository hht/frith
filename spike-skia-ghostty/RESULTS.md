# Spike 结果：Rust + winit 0.31 + skia-safe 0.157 (Ganesh/Metal) + libghostty-vt

回答两个问题：(1) 这套栈能否快速、正确地跑真实 TUI，并在窗口内做毛玻璃；(2) 能否在一个窗口里承载多个面板（分屏、拖拽停靠、重排、调整大小、最大化、最小化到 dock 栏），并把面板拖出成独立窗口、再拖回合并。问题 (2) 的结果见文末「多面板与多窗口」。

测量环境：MacBook（Apple M5 Pro，macOS 26.5），窗口 1200×800 逻辑像素（2400×1600 物理，scale 2），网格 148×50，Menlo 13pt（cell 16×31 px）。均为 `cargo build --release`（strip + thin LTO）。复现命令见 `src/main.rs` 头注释。

## 结论

可行。终端吞吐贴着 macOS PTY 上限，绘制成本远低于帧预算，三个模糊浮窗加在持续刷屏的终端上 GPU p50 只多约 1.4 ms。

## 发现的问题

1. **wuffs 重复符号**：链接警告 `duplicate symbol '_wuffs_base__error__unsupported_option'`，Skia 与 libghostty 各自带一份 wuffs，链接器只保留一份。版本不一致时有 ABI 风险（推断）；正式工程需统一来源或改符号前缀。
2. skia-safe 0.157 的 `metal` 必须同时开 `ganesh`（或 `graphite`），否则 build script 报错。
3. libghostty-rs 的 `Terminal` 为 `!Send`：spike 用「IO 线程只转发字节、终端留在主线程」绕开；正式工程若要把解析移出主线程需 unsafe 包装（未做）。
4. 无 shaping：只取每格首个 codepoint，组合字符 / emoji ZWJ / 连字不正确（已知限制，非测量对象）。
5. σ=20 在 Retina 上下层文字几乎不可辨，视觉上需调小 σ 或减淡染色。
6. **nvim 首字符被改写**：`nvim -c "set number cursorline" -c vsplit src/draw.rs` 启动后，左窗格第 1 行 `//!` 变成 `n/!`（截图 `/tmp/spike-shots/nvim.png`）。推断：某个查询应答（或其缺失后迟到的应答）被 nvim 当作按键解析（`r` `n` = 替换为 n）。未核实；下一步用 `nvim -V3log` 或记录 `on_pty_write` 的字节定位是哪个应答。

7. **Nerd Font 图标显示为 ?**（用户 2026-11-12 实测 powerlevel10k 提示符）：图标在 Unicode 私用区（U+E000–F8FF），系统里没有字体覆盖，回退到 LastResort。用户机器未装 Nerd Font，Ghostty 能显示是因为它内置 Nerd Font 符号字体，并自绘 powerline/框线字形（推断，未核实其源码）。用户决定（2026-11-12）：**不内置字体**，由用户配置指定字体（含回退列表）；**同意自绘** powerline/框线字形。另：atlas 模式用白色字形乘颜色，彩色 emoji 会被染色，需单独走彩色路径。

8. **中文输入显示为 `<00ad>` 转义**（已修复，已验证）：子 shell 继承的环境没有 UTF-8 locale 时，zsh 行编辑器把多字节输入显示为转义（输出不受影响）。修复：`src/term.rs` 在 LC_ALL/LC_CTYPE/LANG 都不是 UTF-8 时设 `LANG=en_US.UTF-8`。验证：`env -u LANG -u LC_ALL -u LC_CTYPE` 下截图 `/tmp/spike-shots/zh-fixed.png` 输入/输出中文正常。

## 多面板与多窗口（2026-11-12）

### 结论

可行，包括拖出拆窗与拖回合并。四个面板同时刷屏时，单帧绘制 p50 0.59 ms；四个空闲面板 CPU 0.0–0.1%。拖出窗口能做的前提是 macOS 在按键按住时把窗口外的拖动事件继续发给按下时的窗口，winit 照转（`winit-appkit-0.31.0-beta.4/src/view.rs:1262-1285` 的 `mouse_motion`：指针在视图外且无按键时才丢弃）。

### 设计

| 模块 | 回答的问题 | 不知道 |
|---|---|---|
| `layout.rs` | 一个窗口的面板如何排布：二叉分屏树 + 最大化 + dock 列表；拆分、移动、交换、最小化、还原、删除；拖放目标与预览区域 | 终端、绘制、窗口事件、装饰 |
| `chrome.rs` | 面板框（标题栏、按钮、内容区）、分隔条、dock 栏的位置，以及一点命中了什么 | 绘制、终端 |
| `gesture.rs` | 一次按下-移动-松开的含义：按钮点击、dock 还原、拖面板、拖分隔条、交给终端 | 布局树、终端、其他窗口 |
| `term.rs` | 一个终端会话：PTY、libghostty-vt、键盘/鼠标/滚轮/粘贴编码 | 屏幕位置、属于哪个窗口 |
| `draw.rs` | 把一帧状态变成 Skia 调用：每窗口一份字形缓存，每面板一份行缓存，装饰与毛玻璃 | 事件、PTY、布局规则 |
| `gpu.rs` | Skia 帧如何上屏：共享一个 Metal 设备与 `DirectContext`，每窗口一个 `CAMetalLayer` | 画什么 |
| `app.rs` | 事件属于哪个窗口和面板；布局变化、跨窗口拖拽、终端输出如何变成重绘 | 上述各模块的内部规则 |

- 面板存于全局表，窗口只持有面板 id 的 `Layout`；跨窗口移动面板只移动 id，终端与子进程不重建。
- 分屏树语义参照 Ghostty（二叉、比例、新拆分 50%、拆分清除最大化、删除时保留幸存者的最大化）：`ghostty-src/src/datastruct/split_tree.zig`，commit `108cacb17ed8990840cd14abfce43d8ed8503ca1`（即 libghostty-vt-sys 构建时拉取的版本）。
- 最小化：面板收进底部毛玻璃 dock 栏，进程继续运行；记录最小化前的邻居和方向，还原时放回原处，邻居已不在则沿同一方向贴窗口边。最后一个平铺面板不能最小化。
- 拖放：落在面板边缘 30% 内拆分该面板；落在中心与之交换（仅同窗口）；落在窗口边 24 逻辑像素内贴整窗口边；松开在所有窗口之外则开新窗口（若源窗口只剩这一个面板，则改为移动该窗口）。
- 解析从「每帧内」移到「PTY 唤醒时」，每面板每次最多 1 MB，防止一个刷屏面板饿死输入与其他面板。
- 跨窗口坐标统一换算为桌面逻辑像素，因为不同显示器的物理像素不同。
- 快捷键尽量沿用 Ghostty macOS 默认：Cmd+D / Cmd+Shift+D 拆分，Cmd+Shift+Enter 最大化，Cmd+[ / ] 切换。

### 验证（脚本驱动真实窗口截图，`/tmp/spike-shots/mp/`）

- m1–m6：拆分出三个面板（zsh、btm、zsh）；最小化进 dock 后 btm 重排为更大尺寸；还原；最大化；把面板拖到窗口右边；拖分隔条后 btm 与 zsh 按新尺寸重绘。
- t1–t4：拖拽中显示毛玻璃落点预览与幽灵卡片；把 btm 拖出窗口，新窗口中 btm 不重启继续运行；再拖回原窗口，新窗口自动关闭。拖回时停靠到上边而非脚本预想的左边，因为新窗口实际位置与脚本推算不同（推断：macOS 把窗口限制在屏幕内）；预览与最终结果一致。
- 脚本运行时忽略真实鼠标事件：首次试跑时用户的鼠标移动改写了脚本拖拽。

### 独立评审后的修复

一个未参与编写的子代理通读了代码。它指出的崩溃先用脚本复现（修复前 panic 于 `app.rs:527`、`layout.rs:435`），修复后同一脚本跑通：

- **手势过期**（3 处可由用户触发的崩溃）：按住标题栏或拖拽中，面板被关闭、子进程退出或被最大化隐藏后，手势和落点预览仍指向它。根因是布局变化后没有和进行中的手势对账。修复：`App::settle` 在每个事件后运行；手势捕获的面板不可见时作废；分隔条拖拽在布局结构变化（`Layout::revision`）时作废；拖拽预览重算。
- **僵尸进程与主线程卡顿**：portable-pty 的 `kill` 在调用线程上发 SIGHUP、轮询约 200 ms 再 SIGKILL，且从不回收（`portable-pty-0.9.0/src/lib.rs:340-371`）。另外，最后一个写端释放时会向 PTY 写入 `\n` + VEOF（`unix.rs:392-403`），子进程若还活着，会执行半截命令行。修复：关闭时把子进程、master 和一个写端移到后台线程，依次 kill、wait，最后释放写端。实测关闭 3 个面板后僵尸进程为 0。
- 其余：Cmd+Q 之后脚本仍访问已关闭窗口；面板移动后在 DEC 2026 保持期间可能空白最多 1 s；松开在别的窗口标题栏上会误拆窗，改为按整个窗口框判定，并跳过最小化窗口；脚本 `\x` 转义遇多字节字符会 panic；删除只被测试使用的死代码。

### 新发现的问题

9. **LastResort 字体遮蔽后续回退**：同一个 btm，在先画过 p10k 私用区图标的窗口里盲文显示为 `?`，在新窗口里正确。推断：私用区字符回退时载入了 LastResort，它声称覆盖所有码位，之后的盲文查找先命中它。与问题 7 的「跳过 LastResort」是同一修复。
10. **图集满时整张清空**：原型只清空不淘汰。已加代次号让行缓存在清空后重建，正式工程需要按 LRU 淘汰或扩容。

### 未做

- 面板内文本选择、标签页、方向键切换焦点、面板标题的重命名。
- 拖拽在窗口外时没有视觉反馈（只能在窗口内画幽灵卡片）；正式工程可用一个无边框小窗口跟随指针。
- 多窗口的 z 序用「最近获得焦点」近似，winit 不提供真实 z 序。
- 窗口间跨不同缩放比例显示器的拖拽未实测（只有一块屏）。

- 关闭面板只给直接子进程发信号；后台任务若继承了 PTY 从端，读线程会等到它们退出。正式工程应向进程组发 SIGHUP（Ghostty 的做法，未核实其源码）。
