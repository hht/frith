# 架构决策记录

只记录用户已批准的决策及其理由；修改已有条目前先问用户。代码与测试是事实来源，这里只写代码里看不出来的「为什么」。

## 1. 核心用 Rust（2026-11-12）

决定：核心用 Rust；不用 Electron、Flutter、React Native、Tauri。
理由：产品目标是小体积、高性能、完整 TUI 支持；上述方案带运行时或 WebView，体积和输入延迟都不达标。

## 2. 插件在独立进程，只提供数据（2026-11-12）

决定：插件是独立进程，经 stdio JSON-RPC 通信；插件从不画 UI，只订阅事件、调用动作、提供数据（命令面板条目、dock 项、徽标）。需要丰富界面的插件，就在一个面板里跑它自己的 TUI。各 AI agent 的集成（识别、用量、通过 Claude Code hooks / Codex `notify` / OSC 9/777 提示「需要注意」）作为官方插件发布。
理由：插件崩溃不拖垮宿主；宿主独占绘制，视觉统一，性能可控。

## 3. 完整 TUI 支持，VT 用 libghostty-vt（2026-11-12）

决定：完整 TUI 支持是硬要求；VT 解析与终端状态用 libghostty-vt；沿用 Ghostty 的配置格式与主题作为卖点。
理由：libghostty-vt 跨平台，覆盖面与 Ghostty 一致。依据见 [调研](research/skia-libghostty-terminal.md) 第 1–3 节。

## 4. 原生非终端面板是相对纯 TUI 工具的优势（2026-11-12）

决定：提供原生的非终端面板（diff、Markdown）；v1 只做一到两种。
理由：这是相对 herdr 等纯 TUI 多路复用器的差异点；数量受控以免拖慢 v1。

## 5. 只内置 Nerd Font 图标字体，文字字体由用户配置（2026-11-12，同日修订）

决定：内置 Symbols Nerd Font Mono（v3.5.1，`SymbolsNerdFontMono-Regular.ttf`，2,610,012 字节，只含图标、不含文字字形），作为回退链中排在系统回退之前的一环；文字字体及其回退列表由用户在配置中指定；回退时跳过 LastResort；powerline（U+E0B0–E0BF）、框线、方块字形由程序自绘。
理由：未装 Nerd Font 的机器上 p10k 等提示符的图标会显示为 `?`（spike 问题 7），用户选择以约 2.6 MB 体积换开箱即用。文字字体仍不内置以控制体积。自绘字形保证提示符与 TUI 边框在任何字体下对齐。
修订前：不内置任何字体。

## 6. 窗口 = 平铺层 + 浮动层，面板不离开根窗口（2026-11-12，同日修订）

决定：
- 应用只有一个根窗口（不提供 Cmd+N 新建窗口）；所有面板（平铺与浮动）都在根窗口内；面板不能拖出根窗口，浮动卡片的位置限制在根窗口内，拖到窗口外松开视为取消。
- 平铺层：二叉分屏树，外观像 TUI 分屏：面板之间只有细分隔线，无间隙、无卡片圆角；布局随增删面板与窗口尺寸自动重算。每个面板一行窄标题，操作按钮（左右拆、上下拆、浮起、最大化、关闭；新拆分各占 50%）只在悬停或聚焦时出现。可拖分隔条调整大小。
- 浮动层：盖在平铺层之上、按 z 序排列的卡片（边框、圆角、阴影），拖标题移动，拖边或角缩放；按钮为最小化、放回平铺、关闭。平铺面板浮起后留在原位置附近。「放回平铺」回到浮起前的位置（原邻居与方向），原邻居已不在则沿同一方向贴窗口边。
- 平铺层可以为空（全部面板都浮起或最小化），此时显示空状态；最后一个面板关闭时应用退出。
- 停靠：拖动面板（平铺或浮动）时显示停靠引导：指针下方的平铺面板高亮为目标，其中心出现上下左右四个方向按钮（拖平铺面板时再加中心「交换」按钮），平铺区四边中点各有一个「贴整窗口边」按钮。指针停在某个按钮上才激活该方向，并显示「停靠区域」预览（半透明区域，大小即松手后面板所占位置）与跟随指针的标签；松手即停靠，原位置由邻居补上。指针不在按钮上时没有停靠：浮动卡片自由移动，平铺面板松手不动。浮动卡片会遮挡其下方的面板，指针在其他浮动卡片上时没有目标面板；已激活的目标面板在指针离开它、但仍在其引导按钮范围内时保持激活（引导按钮画在所有卡片之上，可伸出面板边界）；面板的引导按钮避让窗口边按钮，保证每个按钮都点得到；停靠到浮动卡片上（组成浮动组）另行决定。
- 最大化：一个平铺面板占满整个平铺区，其他面板暂时隐藏，随时可还原。
理由：并排运行多个 AI agent 是产品核心场景。平铺加浮动层是这一类产品的通用模型（Zellij 的 `TogglePaneEmbedOrFloating`、`ToggleFloatingPanes`，见 https://zellij.dev/documentation/keybindings-possible-actions.html）；交互模型沿用，视觉自行设计。停靠预览与「放回平铺回到原位」按业内共识（Windows 贴靠、IDE 的 Dock 回到上次位置）。用户决定面板只在根窗口内活动，不做拖出成系统窗口。
停靠引导按业内共识（Visual Studio、JetBrains、Qt Advanced Docking System 的罗盘式引导）：卡片默认自由移动与精确停靠互不干扰，目标可见。
修订前（停靠）：平铺面板边缘 30% 拆分、中心交换；浮动卡片只在窗口边缘或平铺面板边缘的窄带内停靠；均无可见引导，用户需盲找窄带。
修订前：只有平铺层，面板为带间隙的圆角卡片，平铺面板可最小化；面板可拖出成独立系统窗口并拖回合并（spike 已验证可行）。

## 7. 只有浮动面板能最小化，收进底栏（2026-11-12，同日修订）

决定：浮动面板最小化后收进窗口底栏，成为显示标题和「需要注意」标记的标签，点击恢复为浮动并回到原位置和尺寸；进程继续运行。平铺面板不能最小化，要收起先浮起。
理由：状态只有一条路径（平铺 → 浮动 → 底栏），还原无歧义；最小化的 agent 仍在工作，底栏让它的状态（尤其是「需要注意」）始终可见。
修订前：平铺面板也可最小化，还原时放回原邻居旁。

## 8. UI 层用 winit + skia-safe（Ganesh），终端用 libghostty-vt（2026-11-12）

决定：窗口与事件用 winit，绘制用 skia-safe 的 Ganesh 后端（macOS 上为 Metal），VT 解析与终端状态用 libghostty-vt；不用 GPUI。
理由：spike 两个问题都答「可行」：吞吐贴近 PTY 上限，单帧绘制 p50 约 0.6 ms，四个空闲面板 CPU 0.0–0.1%，release 二进制约 5.5 MB，窗口内毛玻璃与多窗口拖出均已实现。见 [spike 结果](../spike-skia-ghostty/RESULTS.md)。

## 9. v1 范围中的宿主界面（2026-11-12）

决定：v1 做左侧工作区侧栏（项目 → 面板树）与「+」启动器（选 agent 启动，可选在新 git worktree 中）；agent 用量仪表由官方插件提供数据（ADR 2）；浏览器、编辑器、远程主机面板不进 v1。
理由：侧栏与启动器是同时管理多个 agent 的入口；其余功能超出 v1 体量。

## 10. 动画：面板开关用粒子，布局重排用平滑过渡（2026-11-12）

决定：
- 面板（平铺与浮动）开启时由粒子聚拢成形，关闭时飘散为粒子。
- 布局重排（拆分、关闭后的补位、停靠、交换、浮起与嵌回、最大化与还原、最小化与还原）时，受影响的面板从旧位置与尺寸平滑过渡到新位置与尺寸。
- 重排过渡开始时就把终端改到最终尺寸，框按动画插值，超出框的内容裁掉；这样 TUI 的重绘与动画重叠，结束时画面已正确。不逐帧改尺寸，避免每帧一次 SIGWINCH 让 TUI 连续重绘闪烁。
- 拖分隔条和改变窗口大小时不加动画，直接跟手。
- 遵从 macOS「减弱动态效果」：开启时粒子改为淡入淡出，重排过渡瞬间完成。
理由：用户要求的视觉卖点（产品目标中的「醒目 UI」）。
