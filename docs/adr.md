# 架构决策记录

只记录用户已批准的决策及其理由；修改已有条目前先问用户。代码与测试是事实来源，这里只写代码里看不出来的「为什么」。

## 1. 核心用 Rust（2026-11-12）

决定：核心用 Rust；不用 Electron、Flutter、React Native、Tauri。
理由：产品目标是小体积、高性能、完整 TUI 支持；上述方案带运行时或 WebView，体积和输入延迟都不达标。

## 2. 插件在独立进程，只提供数据（2026-11-12）

决定：插件是独立进程，经 stdio JSON-RPC 通信；插件从不画 UI，只订阅事件、调用动作、提供数据（命令面板条目、dock 项、徽标）。需要丰富界面的插件，就在一个面板里跑它自己的 TUI。各 AI agent 的集成（识别、用量、通过 Claude Code hooks / Codex `notify` / OSC 9/777 提示「需要注意」）作为官方插件发布。
理由：插件崩溃不拖垮宿主；宿主独占绘制，视觉统一，性能可控。

## 3. 完整 TUI 支持，VT 用 libghostty-vt（2026-11-12）

决定：完整 TUI 支持是硬要求；VT 解析与终端状态用 libghostty-vt；沿用 Ghostty 的配置格式与主题作为卖点。
理由：libghostty-vt 跨平台，覆盖面与 Ghostty 一致。依据见 [调研](research/skia-libghostty-terminal.md) 第 1–3 节。

## 4. 原生非终端面板是相对纯 TUI 工具的优势（2026-11-12）

决定：提供原生的非终端面板（diff、Markdown）；v1 只做一到两种。
理由：这是相对 herdr 等纯 TUI 多路复用器的差异点；数量受控以免拖慢 v1。

## 5. 内置 JetBrains Mono 与 Nerd Font 图标字体，文字字体可由用户配置（2026-11-12，同日两次修订）

决定：内置 JetBrains Mono 2.304 常规体可变字体（`JetBrainsMono[wght].ttf`，303,144 字节，OFL 1.1，粗体用 `wght` 700，暂不内置斜体）与 Symbols Nerd Font Mono（v3.5.1，`SymbolsNerdFontMono-Regular.ttf`，2,610,012 字节，只含图标）。字体回退顺序与 Ghostty 一致：用户配置的字体中已安装的 → JetBrains Mono → Nerd 图标字体 → 系统按字符回退；配置的字体都未安装时由 JetBrains Mono 决定格子大小。回退时跳过 LastResort。powerline（U+E0B0–E0BF）、框线、方块字形由程序自绘（暂缓）。
理由：用户要求与 Ghostty 一致，Ghostty 内置同一字体并按此顺序回退（`src/font/SharedGridSet.zig`、`src/font/embedded.zig`）；内置文字字体也让 macOS、Windows、Linux 的默认外观一致，不依赖各系统自带字体。用约 0.3 MB 换一致性。未装 Nerd Font 的机器上 p10k 等提示符的图标会显示为 `?`（spike 问题 7），用户选择以约 2.6 MB 体积换开箱即用。
修订前：第一次修订前不内置任何字体；第二次修订前只内置 Nerd 图标字体，文字字体不内置，配置的字体未安装时退回 Menlo。

## 6. 窗口 = 平铺层 + 浮动层，面板不离开根窗口（2026-11-12，同日修订）

决定：
- 应用只有一个根窗口（不提供 Cmd+N 新建窗口）；所有面板（平铺与浮动）都在根窗口内；面板不能拖出根窗口，浮动卡片的位置限制在根窗口内，拖到窗口外松开视为取消。
- 平铺层：二叉分屏树，外观像 TUI 分屏：面板之间只有细分隔线，无间隙、无卡片圆角；布局随增删面板与窗口尺寸自动重算。每个面板一行窄标题，操作按钮（左右拆、上下拆、浮起、最大化、关闭；新拆分各占 50%）只在悬停或聚焦时出现。可拖分隔条调整大小。
- 浮动层：盖在平铺层之上、按 z 序排列的卡片（边框、圆角、阴影），拖标题移动，拖边或角缩放；按钮为最小化、放回平铺、关闭。平铺面板浮起后留在原位置附近。「放回平铺」回到浮起前的位置（原邻居与方向），原邻居已不在则沿同一方向贴窗口边。
- 平铺层可以为空（全部面板都浮起或最小化），此时显示空状态；最后一个面板关闭时应用退出。
- 停靠：拖动面板（平铺或浮动）时显示停靠引导：指针下方的平铺面板高亮为目标，其中心出现上下左右四个方向按钮（拖平铺面板时再加中心「交换」按钮），平铺区四边中点各有一个「贴整窗口边」按钮。指针停在某个按钮上才激活该方向，并显示「停靠区域」预览（半透明区域，大小即松手后面板所占位置）与跟随指针的标签；松手即停靠，原位置由邻居补上。指针不在按钮上时没有停靠：浮动卡片自由移动，平铺面板松手不动。浮动卡片会遮挡其下方的面板，指针在其他浮动卡片上时没有目标面板；已激活的目标面板在指针离开它、但仍在其引导按钮范围内时保持激活（引导按钮画在所有卡片之上，可伸出面板边界）；面板的引导按钮避让窗口边按钮，保证每个按钮都点得到；停靠到浮动卡片上（组成浮动组）另行决定。
- 最大化：一个平铺面板占满整个平铺区，其他面板暂时隐藏，随时可还原。
理由：并排运行多个 AI agent 是产品核心场景。平铺加浮动层是这一类产品的通用模型（Zellij 的 `TogglePaneEmbedOrFloating`、`ToggleFloatingPanes`，见 https://zellij.dev/documentation/keybindings-possible-actions.html）；交互模型沿用，视觉自行设计。停靠预览与「放回平铺回到原位」按业内共识（Windows 贴靠、IDE 的 Dock 回到上次位置）。用户决定面板只在根窗口内活动，不做拖出成系统窗口。
停靠引导按业内共识（Visual Studio、JetBrains、Qt Advanced Docking System 的罗盘式引导）：卡片默认自由移动与精确停靠互不干扰，目标可见。
修订前（停靠）：平铺面板边缘 30% 拆分、中心交换；浮动卡片只在窗口边缘或平铺面板边缘的窄带内停靠；均无可见引导，用户需盲找窄带。
修订前：只有平铺层，面板为带间隙的圆角卡片，平铺面板可最小化；面板可拖出成独立系统窗口并拖回合并（spike 已验证可行）。

## 7. 只有浮动面板能最小化，收进底栏（2026-11-12，同日修订）

决定：浮动面板最小化后收进窗口底栏，成为显示标题和「需要注意」标记的标签，点击恢复为浮动并回到原位置和尺寸；进程继续运行。平铺面板不能最小化，要收起先浮起。
理由：状态只有一条路径（平铺 → 浮动 → 底栏），还原无歧义；最小化的 agent 仍在工作，底栏让它的状态（尤其是「需要注意」）始终可见。
修订前：平铺面板也可最小化，还原时放回原邻居旁。

## 8. UI 层用 winit + skia-safe（Ganesh），终端用 libghostty-vt（2026-11-12）

决定：窗口与事件用 winit，绘制用 skia-safe 的 Ganesh 后端（macOS 上为 Metal），VT 解析与终端状态用 libghostty-vt；不用 GPUI。
理由：spike 两个问题都答「可行」：吞吐贴近 PTY 上限，单帧绘制 p50 约 0.6 ms，四个空闲面板 CPU 0.0–0.1%，release 二进制约 5.5 MB，窗口内毛玻璃与多窗口拖出均已实现。见 [spike 结果](../spike-skia-ghostty/RESULTS.md)。

## 9. v1 范围中的宿主界面（2026-11-12）

决定：v1 做左侧工作区侧栏（项目 → 面板树）与「+」启动器（选 agent 启动，可选在新 git worktree 中）；agent 用量仪表由官方插件提供数据（ADR 2）；浏览器、编辑器、远程主机面板不进 v1。
理由：侧栏与启动器是同时管理多个 agent 的入口；其余功能超出 v1 体量。

## 10. 动画：面板开关用粒子，布局重排用 morph（2026-11-12，同日修订）

决定：
- 面板（平铺与浮动）开启时由粒子聚拢成形，关闭时飘散为粒子。
- 布局重排（拆分、关闭后的补位、停靠、交换、浮起与嵌回、最大化与还原、最小化与还原）时，受影响的面板从旧位置与尺寸 morph 到新位置与尺寸，圆角、边框与卡片阴影随之插值。内容锚定、不拉伸：
  - 面板与面板之间（平铺、卡片）：外框按当前框直接画，终端内容 1:1 锚定在左上角、超出当前框的裁掉；终端在第一帧就按新尺寸重排，与 Ghostty 一致。
  - 面板与底栏标签之间（最小化与还原）：变化发生时把面板旧样子单独离屏画成一张图；面板一侧按宽度等比缩放、锚定左上角，标签按当前框直接画，两者按进度交叉淡化。
  - 每个变形中的面板每帧至多多画一张图。
- 重排过渡开始时就把终端改到最终尺寸；这样 TUI 的重绘与动画重叠，结束时画面已正确。不逐帧改尺寸，避免每帧一次 SIGWINCH 让 TUI 连续重绘闪烁。
- 框的位置与尺寸按 SwiftUI 默认弹簧 `Spring()`（duration 0.5 s、bounce 0，即临界阻尼，0.8 s 停稳）运动；变化中途再变化时保留当前位置与速度。动画时间取帧上屏的时刻。
- 拖分隔条和改变窗口大小时不加动画，直接跟手。
- 遵从 macOS「减弱动态效果」：开启时粒子改为淡入淡出，重排过渡瞬间完成。
理由：用户要求的视觉卖点（产品目标中的「醒目 UI」）。终端的字符网格有固定的像素尺度，resize 时字不变大小、只增减行列，所以内容锚定才是对终端正确的 morph。曾试过 niri 窗口 resize 动画的做法（旧、新两张图拉伸到当前框后交叉淡化，`src/render_helpers/shaders/resize.frag`，commit 589bc40），截图显示标签文字被拉成巨字、缩小 30 pt 的平铺面板文字错半行重影，故只在面板缩进或长出标签时用截图，且等比缩放。标签在 morph 落地前不另画，不会提前出现。缓动用 Apple 的，由用户指定；弹簧在中途变向时保留速度，过渡连贯。开销与内容多少无关（`CLAUDE.md` 原则 3）。
修订前：框按动画插值，超出框的内容裁掉，未指定缓动；同日一度改为所有过渡都按 niri 做法拉伸并交叉淡化，见上述截图后改为锚定。

## 11. 自带极简 shell 集成，只做提示符标记（2026-11-12）

决定：按 OSC 133 公开规范自行编写极简 shell 集成，只发提示符标记（`133;A;redraw=1`、`B`、`C`、`D`），让终端在 resize 时清掉旧提示符、由 shell 重绘。先做 zsh（macOS 默认 shell），bash、fish 随后。注入方式参照 Ghostty（MIT）的 `src/termio/shell_integration.zig`：zsh 用 `ZDOTDIR` 指向集成目录，先恢复用户原有 `ZDOTDIR` 并加载其 `.zshenv`。不复制 Ghostty 或 Kitty 的集成脚本。
理由：libghostty-vt 的 C API 默认不清除提示符（`c/terminal.zig:1056`，`shell_redraws_prompt = .false`），且无选项可改，只能由 shell 以 `redraw=1` 开启；没有标记时窗口 resize 会堆叠提示符。只合并 resize（已实现，25 ms）只能减少次数。Ghostty 的 zsh、bash 集成脚本为 GPLv3（源自 Kitty），直接内置会约束产品授权；自写只含所需部分。
脚本落盘（2026-11-12 补充）：脚本以 `include_str!` 编进二进制（约 2 KB），启动时写到用户缓存目录下以内容哈希命名的子目录（macOS 为 `~/Library/Caches/frith/shell-integration/<哈希>/`），已存在则跳过；先写临时目录再改名，多个实例同时启动也不会读到写了一半的脚本；写不进时跳过集成并提示。理由：Frith 目前是裸二进制，没有 Ghostty 那样的 app bundle 资源目录；有了 bundle 后可改为随包分发。

## 12. 不内置统一的 shell 主题，修渲染（2026-11-12）

决定：不替换或覆盖用户的 shell 提示符主题（如 p10k）。提示符与 TUI 显示不对，从渲染根因修：按 ADR 5 自绘框线、powerline、块字形（含 ░▒▓），文字字体改为可配置；终端配色主题按 ADR 3 沿用 Ghostty 主题，与此互补。
理由：p10k 的框线断开、分隔符不贴合等问题来自字体字形未填满格子与自绘字形未实现，同样影响 starship、vim、htop；改用户主题违反「TUI 表现与参考终端一致」。

## 13. 配置用 Ghostty 格式，没有 Frith 配置时读 Ghostty 的（2026-11-12）

决定：Frith 读取自己的配置文件，语法与键名沿用 Ghostty（`key = value`，`#` 开头为注释，值可加双引号，空值恢复默认，`font-family`、`palette` 可重复）。Frith 的配置文件不存在时，按 Ghostty 的顺序读取用户的 Ghostty 配置（先 `$XDG_CONFIG_HOME/ghostty/`，再 macOS 的 `~/Library/Application Support/com.mitchellh.ghostty/`）。不认识的键忽略并提示。`theme` 暂不支持。配置的字体未安装时按 ADR 5 退回内置的 JetBrains Mono，与 Ghostty 一致。第一步支持字体、字号、前景与背景色、光标色、调色板、内边距；背景透明、模糊、`font-thicken` 另行调研。
理由：用户截图对比显示，Frith 与其 Ghostty 的差异全部来自配置（背景、字体、字号、调色板、内边距），而 256 色色块的显示值完全一致。读取已有 Ghostty 配置可让用户开箱即得同样外观，兑现 ADR 3「沿用 Ghostty 的配置格式与主题」。

## 14. 外框视觉语言：取自终端、系统字体、淡化未聚焦面板（2026-11-12）

决定：
- 推进顺序：先保证内容显示正确（ADR 11 shell 集成、ADR 12 自绘字形），再统一外框外观，然后做动效（ADR 10）、毛玻璃、侧栏（ADR 9）。
- 外框配色取自终端背景：顶栏、面板标题行、底栏、卡片按终端背景色的亮度推导出几档相近的色阶，不再使用独立的固定配色；强调色取调色板 4 号色；外框文字与其底色的对比度不低于 4.5:1（WCAG 1.4.3），极亮或极暗的主题也要满足。
- 外框文字（标题栏、面板标题、标签、提示）用系统 UI 字体（macOS 为 SF，Windows 为 Segoe UI），经 Skia FontMgr 取用，不内置字体；终端网格仍用 ADR 5 的字体。
- 未聚焦的面板淡化：按 Ghostty 的做法在其上叠一层半透明矩形，读取 `unfocused-split-opacity`（默认 0.7，限制在 0.15–1）与 `unfocused-split-fill`（默认终端背景色）。
- 底栏只在有最小化卡片时出现。
- 面板标题只显示在面板标题行，顶栏不再重复显示焦点面板的标题。
- 外框按钮的点击区不小于 24×24 逻辑像素（WCAG 2.5.8）。
理由：用户要求把 UI/UX 推进到一流水平。终端内容占窗口绝大部分像素，内容显示不对时外框的打磨没有意义，配色也要以正确的内容为准来校准。外框与终端背景同色是 Ghostty 默认 `macos-titlebar-style = transparent` 的做法（`src/config/Config.zig`），换主题后外框自动协调。系统 UI 字体体积为零，与原生应用一致；内置 Inter 会增加约 0.3–0.8 MB（未实测），违背「小体积」。并排运行多个 agent 时焦点位置是最关键的信息，淡化未聚焦面板是 Ghostty 的默认行为（`unfocused-split-opacity` 默认 0.7）。
